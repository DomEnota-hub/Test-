# ТЭМ2 / ТЭМ2У — Stage 1 checkpoint

Дата: 2026-10-02

Статус: **STAGE_1_FOUNDATION_COMPLETE**.

Этот checkpoint закрывает только фундамент семейства ТЭМ2. Атлас, электрические/пневматические схемы, интерактив, диагностика, семантика ассистента и Приёмка относятся к следующим отдельным этапам и здесь не объявляются готовыми.

## Профили

Каноническая структура:

- `common/` — только подтверждённый общий слой семейства;
- `tem2/` — профиль `tem2-base`;
- `tem2u/` — профиль `tem2u-improved`.

Оба профиля на Stage 1 имеют только `completedStages=[FOUNDATION]` и остаются `FOUNDATION_ONLY_NOT_READY_FOR_APP_INTEGRATION`.

Разделение исполнения строится не только по надписи серии. Для будущей маршрутизации введены измерения фактического исполнения дизеля, электрической схемы, тормозного оборудования, органов управления и локальной модернизации. При неизвестном исполнении вариантозависимые эксплуатационные действия fail-closed.

Два источника Stage 1 имеют статус `CURRENT_CONFIRMED`: действующие правила тормозов и правила охраны труда. Заводские руководства используются как подтверждение заводского исполнения и архитектуры, а не как автоматический текущий допуск к действиям.

## Изоляция соседних модификаций

ТЭМ2У не трактуется как «любая поздняя ТЭМ2». Явно запрещено автоматическое наследование:

- ТЭМ2УМ — в том числе предположений о 1ПД-4А / повышенной мощности и собственной электрической схеме;
- ТЭМ2Т — реостатного/электродинамического тормоза, тормозных резисторов и связанных действий;
- ТЭМ2А — специфики колеи/экспортного исполнения;
- ТЭМ15 / ТЭМ17 / ТЭМ18 — оборудования и логики более поздних семейств.

Для ТЭМ2У отдельно подтверждена необходимость собственного электрического слоя; профиль также содержит заводские признаки оборудования управления в одно лицо, работы по системе многих единиц, дополнительных постов управления и регулятора напряжения БРН-3В. Конкретное наличие после ремонтов/модернизаций всё равно требует подтверждения фактической комплектации.

## Инфраструктурная граница foundation → Android runtime

При регистрации нового семейства обнаружена архитектурная проблема: старый `qa/build_source_presentations.py` автоматически проецировал в Android все source-registry из `docs/locomotives`, даже если локомотив находился только на Stage 1.

Это исправлено. Теперь новый источник попадает в Android `source_presentations.json` только когда его ID уже входит в интегрированный presentation contract либо реально используется runtime-asset. Само наличие foundation-реестра больше не означает скрытую интеграцию незавершённого локомотива.

После исправления существующая Android-проекция ЧМЭ3 и compile/unit tests снова проходят; новые источники ТЭМ2 остаются за runtime-boundary до отдельной интеграции.
