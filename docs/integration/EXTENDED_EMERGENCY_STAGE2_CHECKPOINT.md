## Источниковый корпус и дедупликация

Stage 2 source corpus содержит **29** нормализованных source records. Для каждого сохранены происхождение, тип, provenance-class, статус, эпоха, применимость, mirror-group и authority boundary.

`mirrorGroup` обязателен: несколько перепечаток одного материала не считаются несколькими независимыми подтверждениями. Публичные коллекции и индексы `DISCOVERY_ONLY` могут помогать находить документ, но не могут быть единственным основанием кандидата.

Отдельно зафиксирован действующий safety-framework по аварийным схемам локомотивов. Он подтверждает саму организационную возможность применения утверждённых аварийных схем, но одновременно требует привязки к серии/утверждённому порядку соответствующего подразделения. Поэтому framework не повышает ни один найденный исторический или полевой способ до текущего разрешённого действия автоматически.

## ЧМЭ3 / ЧМЭ3Т / ЧМЭ3Э

Для базового ЧМЭ3 найден широкий практический корпус: аварийные схемы тяги и пуска, способы восстановления цепей управления, исторические/полевые решения по возбуждению, компрессору, охлаждению, регулятору дизеля, топливной системе и другим отказам.

Высокорисковые методы, предполагающие обход защиты, перемычки, принудительное удержание/включение аппаратов, вмешательство в высокотоковую схему или работающий вращающийся механизм, на Stage 2 классифицированы `PROHIBITED`. В нормализованном inventory не хранится procedure-level последовательность их выполнения.

Для `CHME3-DIAG-319` (буксовый узел) и `CHME3-DIAG-320` (тяговый редуктор) целевой поиск не дал отдельного резервного метода, который можно было бы честно зафиксировать как expanded-кандидат без выдумывания процедуры; обе ветви получили `NO_ADDITIONAL_METHOD_FOUND`.

Stage 1 gap по ЧМЭ3Т частично закрыт: найден профильный технический материал по реостатному/электродинамическому торможению и возможным неисправностям. Поэтому `CHME3-DIAG-110` получил один профильный `INFORMATION_ONLY` кандидат только для `chme3t-rheostatic`. Это историческая техническая база, а не подтверждение актуального разрешения на действие.

Для двенадцати ЧМЭ3Э-специфичных веток найдены профильные описания оборудования и схем, но отдельный доказуемый резервный способ для каждой конкретной неисправности открытый поиск не дал. Все **12/12** отмечены `NO_ADDITIONAL_METHOD_FOUND`; базовые аварийные схемы ЧМЭ3 к электронному исполнению не наследуются.

## ТЭМ2 / ТЭМ2У

Для ТЭМ2 найден расширенный корпус по пуску, тяговой цепи, возбуждению, защитам, регулированию оборотов, зарядке, компрессору, тормозам, охлаждению и аварийной топливной ветви. Заводские и исторические материалы рассматриваются как доказательство существования метода/конструктивной возможности, но сами по себе не являются текущим разрешением для локомотивной бригады.

Для `TEM2-DIAG-022` (управление одним лицом) и `TEM2-DIAG-023` (СМЕ) отдельного резервного метода при достаточной профильной определённости не найдено. Обе ветви остаются `NO_ADDITIONAL_METHOD_FOUND`; методы базового ТЭМ2 туда не наследуются.

Для `TEM2-DIAG-024` найдено отдельное свидетельство аварийной топливной ветви ТЭМ2У в материалах исполнения ТЭМ2У. Оно хранится отдельным `tem2u-improved` кандидатом и не выводится из кандидата ТЭМ2 по родству серии.

## Safety / authority boundary

Stage 2 намеренно не повышает ни один диагностический способ до `CONDITIONAL_ACTION`.

Даже если метод повторяется в нескольких старых/полевых источниках, это доказывает распространённость описания, но не текущую допустимость. Для перехода на следующем этапе потребуются как минимум:

1. точная применимость к фактическому исполнению;
2. источник, достаточный для конкретного действия, а не только описания симптома/схемы;
3. проверка актуальности/редакции и отсутствия конфликта;
4. необходимый safety-gate;
5. для локально утверждаемых аварийных схем — соответствующий утверждённый порядок, а не только публичная копия старой схемы.

Неизвестное или модернизированное исполнение остаётся `FAIL_CLOSED`. Смежные варианты не наследуют expanded-методы автоматически.

## Переход к Stage 3

Stage 3 может строить runtime-v2 / assistant semantics только поверх этого нормализованного корпуса. `PROHIBITED` остаётся неисполняемым независимо от включённого расширенного режима. `INFORMATION_ONLY` не должен превращаться в команду пользователю только потому, что режим включён.

Любое будущее повышение до `CONDITIONAL_ACTION` должно быть отдельным доказуемым решением с provenance, profile gate и safety gate; текущий Stage 2 такого повышения не содержит.
