# Ассистент — рабочая ветка нативных макетов (Framework v2)

Статус: создана изолированная ветка для проектирования; это не утверждение готового дизайна и не изменение релизной версии.

## Подтверждённая база

- Репозиторий: `DomEnota-hub/Test-`.
- Исходная ветка: `feature/diagnostic-framework-v2`.
- Исходный коммит: `3176d6ee228f0ed4b78371f45209e10c1c724eff` (06.10.2026).
- В `app/build.gradle.kts`: `versionCode = 203`, `versionName = "1.2.2-dev14-framework-v2-test"`.
- Получен APK `RailBrakeCalculator_VL80S_Assistant_74_steps_signed.apk`: в AndroidManifest подтверждены package `ru.railbrake.calculator`, versionCode `203`, versionName `1.2.2-dev14-framework-v2-test`, minSdk `26`.
- Из этого APK два ресурса `assets/technical/diagnostic_framework_v2.json` и `assets/technical/source_presentations.json` совпали побайтово с ресурсами исходной ветки (Git blob SHA: `ab2ecd3f58256a1d4d260dc17ec334ee8fe4d12d` и `6dde42099f5c6e9f1226212ae5e42c6a04fde00c`).
- Сборка не содержит исходный SHA: `META-INF/version-control-info.textproto` указывает `NO_SUPPORTED_VCS_FOUND`; нельзя утверждать, что APK побайтово собран именно из коммита `3176d6ee`. Совпадение имени, кода и ресурсов установлено.
- Compose-экраны рисуются при выполнении Android-приложения, поэтому APK не даёт готовых скриншотов. Для визуального эталона потребуются снимки на устройстве либо проверенный запуск в эмуляторе.

## Границы и источник истины

- Только `Test-`; `Beta` запрещено изменять до прямого разрешения.
- Новые экраны проектировать **нативно на Jetpack Compose**, в рамках навигации, технического каталога и AssistantRuntime данной ветки. Не переносить структуру Beta.
- Сохранять рабочие обработчики, данные, голосовой ввод, локомотивные профили, диагностические сценарии и расчётную логику. Первые изменения — только представление/UI.
- Опора на реально существующие `HomeScreen.kt`, `AssistantHomePanel.kt`, `RailDesign.kt`, `BrakeCalculatorApp.kt` и `ui/theme/`.
- Макеты должны соответствовать качеству и плотности реального приложения, а не упрощённому HTML-каркасу или генеративному изображению.
- Предусмотреть светлую и тёмную темы; настройки произвольной палитры в целевом интерфейсе не будет. Пока не менять настройки темы в работающей версии.
- Никаких придуманных железнодорожных нормативов, расчётных итогов, диагностических выводов, «исправных» статусов и фиктивных записей, которые могут быть приняты за настоящие.

## Согласованная композиция главной

1. Настоящий хедер приложения с боковым меню и ОПП.
2. Выбор рабочего локомотива **по списку Test**, не сводить каталог к ВЛ80С/Ермаку.
3. Действующий офлайн-Ассистент с поиском и текущими возможностями.
4. Диагностика и Атлас оборудования; сохранить доступность Базы знаний в согласованной навигации.
5. **Карточка «Расчёты» на главной — обязательна** (последнее прямое уточнение пользователя от 14.10). Внутри без лишнего промежуточного экрана: «По массе», «ИДП №12», «ВУ-45». Наличие ВУ-45 в эталонной ветке **не предполагается**; интеграция из отдельной экспериментальной ветки — самостоятельный шаг.
6. Рабочие записи: замечания при приёмке, история расчётов, история диагностики, личные заметки. При наличии подтверждённых открытых замечаний — их быстрый доступ с главной. Не подменять этот блок «последним расчётом».


## Уточнение ранее утверждённого UI (13–14.10.2026)

- **Официальное название приложения — «Ассистент»**, не «Железнодорожный помощник». Применять к шапке, меню и макетам. Подзаголовок «Помощник локомотивной бригады» обсуждался как вариант, но не считать его безусловно утверждённым.
- **Выбор локомотива уже согласован:** вместо горизонтальной ленты чипов — одна компактная карточка «Рабочий локомотив»; нажатие открывает окно выбора, серии сгруппированы по типам. На главной выводить только выбранную модель. Год, номер и исполнение не запрашивать обязательно; уточнять лишь при реальной необходимости.
- Рабочая серия и серия, которую пользователь временно просматривает в Атласе/справочнике, — разные контексты. Просмотр другой серии не меняет рабочий выбор. Списки строить из общего реестра Test.
- Не возвращаться к обсуждению «горизонтальный скролл чипов / перенос на две строки / отдельный экран» без прямого запроса пользователя: соответствующее решение принято.

## Порядок реализации и контроля

1. Эталонный APK версии 203 получен и проверен по манифесту/двум ресурсам. Получить и сверить **живые Android-снимки** главной в обеих темах, включая прокрутку и открытое меню. Только APK недостаточно для оценки визуального рендера.
2. Внести первые изменения только в новой ветке, выделяя переиспользуемые Compose-компоненты. Не заменять рабочий `AssistantHomePanel` заглушкой.
3. Подготовить реальные Android-превью или снимки из сборки; обе темы должны быть видны для согласования.
4. Запустить доступные проверки сборки; отдельно зафиксировать то, что не удалось проверить (например, эмулятор).
5. После визуального одобрения переходить к следующим экранам и только затем обсуждать объединение веток.

- «Рабочие записи» с архивом, черновиками, медиа и резервированием не появляются автоматически.
- Базовая версия 203 и другие экспериментальные ветки остаются как были.
